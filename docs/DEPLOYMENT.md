# 部署清单（吸收自团队 edge-cloud-prototype 的版本固定纪律）

目标：同一份代码在任何机器上跑出**可复现**的实验——版本固定、来源校验、
失败不静默降级。核对完本清单再开始正式实验。

## 1. 版本固定（部署前填入，禁止"最新版"）

| 组件 | 固定方式 | 本次取值 |
|---|---|---|
| llama.cpp / Ollama | 固定 commit / 版本号 + 下载源 SHA256 | ______ |
| 本地模型 | 仓库 + revision + 发布方 SHA256 | ______ |
| 云端模型 | 精确 model 名（含日期版本，如 deepseek-chat 的快照） | ______ |
| Python | 版本下限 3.10，记录实际版本 | ______ |

双源下载规则：镜像源（hf-mirror 等）与官方源都必须通过**同一个** SHA256 校验；
只有一方可校验时停下，不继续。

## 2. 预检查（不通过不开始）

- [ ] GPU 可见（`nvidia-smi`），驱动主版本 ≥ 570（llama.cpp CUDA 构建经验值）
- [ ] CUDA toolkit ≥ 12.8（自编译 llama.cpp 时）/ 或使用 Ollama 官方构建
- [ ] 磁盘 ≥ 10 GiB（模型 + 运行时 + SQLite 落库）
- [ ] 本地服务健康：`curl $OLLAMA_HOST/api/tags` 返回模型列表
- [ ] **模型列表成功 ≠ 生成可用**：跑一次真实生成确认（`python -m dot_agent.cli` 类入口或 demo）
- [ ] GPU 加载确认：服务日志须显示 GPU 层加载；只用 CPU 跑出的结果**不得**作为 GPU 验收

## 3. 密钥纪律

- API key 只经环境变量 / 权限 600 的本地文件注入，不写代码、不进命令行参数、不入日志
- 不把密钥文件下载到其他机器或收入交付包
- 仓库内只放 `.env.example` 一类占位

## 4. 实验前

- [ ] warmup 预热已完成（首调含模型加载，实测可达数十秒；不预热 P95 失真）
- [ ] 每轮实验独立 `--run-id`；报告文件已存在则换新名，不覆盖
- [ ] 随机种子与温度已固定并记录在 run_id 对应的配置里
- [ ] 评测四模式逐题轮换执行顺序（runner 默认行为，勿改）

## 5. 实验后（诚实边界自查）

- [ ] `unknown_usage_calls > 0` 的行：C_API 是已知部分小计，报告必须注明
- [ ] stub 模式跑出的任何数字不得进入正式报告（只作流程烟测）
- [ ] 小样本（n < 30）只描述不推断；不宣称"统计显著"
- [ ] SQLite（data/metrics.db）随报告归档：calls/tasks 原始记录是口径争议时的证据

## 6. 失败处理红线

- 编译/加载失败：不静默回退 CPU，修好环境再跑
- 云端不可用：降级本地会如实记双档位（cloud_fallbacks），报告中注明降级率；
  降级样本是否计入云端对照组，需在报告开头声明
- 任何一次"绕过计量层的调用"都视为实验作废（MeteredClient 是唯一出口）
